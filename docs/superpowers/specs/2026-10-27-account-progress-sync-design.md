# 地图题口袋卡：账号登录与跨设备进度同步

日期：2026-10-27（Asia/Shanghai）  
状态：方案待用户审阅；产品代码与线上页面尚未修改。  
基础版本：`8eb700b1a0c80bf4e574b12685f064d471d8a833`

## 1. 用户目标与已确定事项

用户已选择“账号登录同步”。同一个人在手机与电脑登录同一账号后，可以共享词卡熟悉度和继续背诵的位置。两端已有进度应保留，网络失败不应造成进度丢失。

现有网站继续在 https://flyyuan1.github.io/ielts-map-pocket/ 提供服务。132 条表达、翻卡、听音、自测、词表、打印和离线下载继续可用。现有浏览器语音能力不在本次改动范围内。

本方案采用邮箱和密码登录；网页访问和未登录学习继续开放。新增 Supabase Auth 与 PostgreSQL 作为账号和私有进度存储，不将 GitHub 仓库用作用户数据库，不依赖已受访问拦截影响的 chatgpt.site 域名。

## 2. 当前问题

`index.html` 中的 `persist()` 仅将 `{ marks, filter, cat, position }` 写入当前浏览器的 `ielts-map-pocket-v1`。不同设备、浏览器及域名之间没有共享存储，也没有登录或云端接口。

原始标记没有修改时间与版本号，因此不能可靠判断两台旧设备上相反标记的先后顺序。迁移时不能假称“已识别最后修改的那一次”。

## 3. 使用流程

### 登录与账号管理

- 页头新增“登录同步”入口，支持邮箱密码登录、注册、退出登录及通过邮件找回密码。
- 注册后的验证邮件和密码找回邮件由认证服务发送；回跳地址精确配置为现有 GitHub Pages 页面。
- 登录后显示账号与同步状态。两台设备可同时登录，退出只结束当前设备的会话。
- 未登录或认证服务无法访问时，仍可使用本地学习功能。
- 不在网页内保存用户明文密码；令牌的保存、刷新与认证回调由官方客户端处理。

### 第一次合并旧数据

- 在修改任何本地数据前，保存原 `ielts-map-pocket-v1` 的完整备份。
- 发现未归属账号的旧标记时，提供一次“合并这台设备的已有进度”操作，并显示待合并的标记数。
- 两端不同卡片的标记取并集；没有标记的卡片不覆盖云端已有标记。
- 同一卡片旧记录冲突时，将“不熟”优先保留，并显示合并提示。这是明确的学习策略，不推断不存在的历史时间。
- 原站 chatgpt.site 的浏览器存储无法被新域名直接读取。本次可迁移的数据是当前 GitHub Pages 域名在各设备中已有的进度；原域名数据需要另行导出后才能导入。
- 旧数据导入按账号与设备记录完成标记，刷新或重新登录不会重复导入。备份不会在导入成功后自动删除。

### 日常同步

- 点击“记住了”“还不熟”或词表星标后，先更新本地界面与待上传队列，再同步云端。
- 登录完成、页面重新获得焦点、恢复网络、手动点击“立即同步”时执行拉取与补传。
- 页面处于前台并已登录时，每 15 秒检查一次更新；后台暂停轮询。网络或认证失败时退避，防止持续重复请求。
- 手机和电脑同时打开时，另一端在下次轮询或重新激活页面后显示更新，不要求实时推送。
- 背诵位置按稳定的词卡 ID 保存，同时保留分类与学习范围。不能直接依赖过滤后会变化的数组下标。
- 云端位置仅在初次载入且用户尚未开始本轮操作时用于“继续背诵”；远端变化不会把正在看的卡片突然切走。

## 4. 前端结构与离线行为

- 保留当前静态站，新增独立的账号界面、同步控制器和可单独验证的进度合并模块。
- 官方认证客户端打包进站点静态资源，不依赖第三方脚本 CDN。
- 公开配置只包含项目地址与可公开的客户端密钥。管理密钥与服务端权限密钥不进入 GitHub 仓库或浏览器。
- 保留原本地存储作为未登录数据与迁移来源。账号缓存、设备 ID、待上传队列和迁移记录按用户 ID 分开保存。
- 登录账号 A 后退出再登录账号 B，不读取、展示或上传 A 的账号缓存；A 未上传的操作保留在 A 的队列中。
- 上传响应返回前若账号改变，旧响应不能修改新账号页面或删除新账号队列。
- 离线下载生成包含词表、字体和学习逻辑的独立 HTML；不将登录令牌、邮箱、密码输入值或账号私有数据写入下载文件。
- 下载的离线版继续提供本地学习，不承诺 file:// 页面自动登录云端。浏览器中的联网版支持断网学习和联网补传。

## 5. 云端数据与权限

采用以下逻辑表，数据库迁移脚本随源码保存：

| 数据 | 主键 | 必要内容 |
| --- | --- | --- |
| `study_marks` | `user_id, card_id` | `status`（known / weak / new）、服务端版本、服务端更新时间 |
| `study_view_state` | `user_id` | 当前词卡 ID、学习范围、类别、服务端版本与更新时间 |
| `study_sync_operations` | `user_id, operation_id` | 幂等操作 ID、请求摘要与处理结果，供重试去重 |

`new` 表示明确取消标记的状态。云端保留其版本，防止旧设备恢复联网后重新带回已取消的旧标记。

- `user_id` 由已验证的认证身份取得，不信任网页提交的其他账号 ID。
- 所有用户数据启用行级权限，未登录用户不能读写；登录用户只能访问自己的记录。
- 所有状态、词卡 ID、分类、学习范围与请求大小均校验。只接受现有 132 张卡片的 ID。
- 服务端维护递增版本和更新时间，不能信任客户端时钟决定冲突胜负。
- 提供一个数据库事务函数完成当前账号的批量合并、版本检查、幂等去重和结果返回。锁定或按稳定顺序处理相关记录，保证并发写入的一致性。
- 函数与表权限均按最小范围授予；测试直接 REST 请求与函数调用均不能越权读取或写入其他账号。

## 6. 合并与并发规则

- 不同卡片分别更新，不能用一台设备的整份快照覆盖另一台设备的进度。
- 本地操作携带独立操作 ID 和最后已知的云端版本。相同操作重试只执行一次。
- 基础版本仍有效时应用用户的新选择，因此后续明确把“不熟”改为“记住了”可以正常生效。
- 同一卡片的基础版本过期且双方状态相反时，使用 `weak > known > new` 的保守合并顺序，返回合并结果并在界面提示。取得新版本后，用户可以再次明确修改。
- 同状态的重复修改不产生内容冲突。
- 同步成功只移除云端明确确认的队列项；失败或不完整响应不清空队列。
- 位置与筛选使用独立记录；不影响卡片熟悉度的合并，也不会因位置冲突丢失标记。

## 7. 状态与失败处理

界面显示“仅保存在本机”“正在同步”“已同步”“离线，联网后自动同步”或“需要重新登录”。提供可操作的重试入口。

登录失败、邮箱验证未完成、邮件发送失败和网络不可达分别给出明确提示。不会把任一失败显示成“已同步”。

会话过期时保留账号队列并暂停上传，重新登录同一账号后继续。失败重试采用有上限的指数退避；页面重新获得焦点或用户手动同步时可立即重试。

## 8. 接入前置条件与发布顺序

1. 用户添加并授权 Supabase，使可用项目与配置能够被核实。目前尚未确认该连接已建立。
2. 选择用户拥有的现有项目；如不存在合适项目，则在明确的账号和方案下新建专用项目。未确认服务方案前不创建付费资源。
3. 核对邮箱登录、验证和密码找回的实际发送能力。Supabase 默认发信服务有收件人与使用限制；如现有配置不满足本网站使用，需配置发信服务后再发布注册与找回功能，不通过关闭验证掩盖缺失能力。
4. 配置本站回跳地址、数据库迁移、行级权限与公开客户端配置。
5. 先验证认证接口、数据库访问与账号隔离，再连接前端。新后端的中国移动实际可达性需要用户设备验证；不能由本机访问成功推断。
6. 完成下述验收后更新 GitHub Pages。未接通云端前不发布一个看似可登录、实际上不能同步的界面。
7. 若后端接入或网络验证失败，保留当前已上线版本和本地进度，报告具体阻碍后调整服务选择。

## 9. 验收标准

- 两个独立浏览器会话以同一账号登录：一端标为“已记住”，另一端在 15 秒内或手动同步后显示相同结果。
- 设备 A 与设备 B 同时修改不同卡片，两份修改均保留。
- 同卡并发冲突符合保守合并规则；同步后再次明确改成“已记住”能生效。
- 模拟离线标记、重载页面、恢复网络，待上传操作不丢失、不重复应用。
- 两端旧进度合并后卡片集合完整，空白设备不能清空已有云端进度。
- 两个不同账号与未登录请求均无法读取或修改对方数据；切换账号不串缓存或队列。
- 注册、邮箱验证、登录、当前设备退出与密码找回完整走通；测试会话失效与错误密码。
- 320px 与 390px 宽度下账号界面可操作，无页面横向溢出；现有 132 条词表、翻卡、自测、搜索、朗读触发与离线下载不回退。
- 检查公开源码、静态产物、下载 HTML 与日志，确保没有服务端密钥、测试密码或用户会话令牌。
- GitHub Pages 部署成功，线上产物与预期一致。对中国移动网络的可用性单独记录，未实际验证时明确说明。
